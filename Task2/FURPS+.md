| F   | Функциональные (Functionality)                                                                                                                                                                                       |                                                                                                                          |
| F1  | Сайт должен отображать список доступных депозитов с актуальными процентными ставками для неавторизованных пользователей.                                                                                             | Источник данных о ставках должен быть единым (новый сервис или доработка АБС).                                           |
| F2  | Сайт должен позволять новому клиенту подать заявку на депозит, указав ФИО и номер телефона.                                                                                                                          | Заявка передаётся в систему для обработки менеджером кол-центра.                                                         |
| F3  | Интернет-банк (ИБ) должен отображать для авторизованного клиента список депозитов с актуальными и персонализированными ставками.                                                                                     | Персонализация ставок требует интеграции с системой управления ставками и данных о клиенте                               |
| F4  | ИБ должен позволять клиенту подать заявку на депозит с выбором счета и суммы, с подтверждением операции через СМС-код.                                                                                               | Подтверждение через СМС — существующий функционал, но требуется его адаптация.                                           |
| F5  | Заявки, поданные через сайт и ИБ, должны поступать в бэк-офис для обработки менеджером (на MVP).                                                                                                                     | Определяет необходимость интеграции между новыми каналами и АБС/системой кол-центра.                                     |

| F7  | Сотрудники бэк-офиса (депозиты и кредиты) должны иметь возможность управлять ставками по депозитам (актуализация, персонализация) через единый интерфейс.                                                            | Сейчас ставки в Excel. | F8  | Сайт должен отображать кредитные предложения (из Кредитного конвейера) и позволять новому клиенту подать заявку с ФИО и телефоном; при заполнении паспортных данных – выполнять скоринг через БКИ и выдавать решение.| Требует онлайн-интеграции с Кредитным конвейером и Скорингом, а также с БКИ.                                             |
| F9  | ИБ должен отображать предодобренные кредитные предложения и позволять подать заявку с подтверждением СМС.                                                                                                            | Предодобренные предложения должны рассчитываться заранее (фоновый скоринг).                                              |
| F10 | Система должна обеспечивать связь заявок, поданных через сайт/ИБ, с заявками в отделении (чтобы менеджер видел историю и предодобрение).                                                                             | Требует единого идентификатора клиента и заявки, синхронизации между АБС, Конвейером и новыми каналами.                  |
| F11 | Клиент должен получать СМС-уведомления об изменении статуса кредитной заявки.                                                                                                                                        | Расширение функционала СМС-информирования.                                                                               |
| F12 | Все каналы передачи чувствительных данных (сайт, ИБ, внутренние сервисы) должны использовать шифрование (TLS/HTTPS).                                                                                                 | Обеспечение безопасности персональных данных, соответствие законодательству.                                             |
| U   | Удобство использования (Usability)                                                                                                                                                                                   |                                                                                                                          |
| U1  | Интерфейсы сайта и ИБ должны соответствовать корпоративной дизайн-системе (цвета, элементы бренда).                                                                                                                  | Обеспечивает единый пользовательский опыт.                                                                               |
| U2  | Время отклика при выполнении операций (подача заявки, отображение страниц) должно стремиться к миллисекундам; необходимо устранить текущие задержки >1 сек при загрузке справочных данных.                           | Требует оптимизации производительности, возможно, кэширования и рефакторинга.                                            |
| U3  | Процесс подачи заявки должен быть интуитивно понятным, с подсказками и минимальным количеством шагов.                                                                                                                | Соответствие лучшим практикам UX.                                                                                        |
| U4  | Интерфейс для сотрудников бэк-офиса по управлению ставками должен быть удобным, с возможностью быстрого просмотра и редактирования.                                                                                  | Повышение эффективности работы.                                                                                          |
| R   | Надёжность (Reliability)                                                                                                                                                                                             |                                                                                                                          |
| R1  | Доступность сервисов интернет-банка и сайта должна быть не менее 99,9% в режиме 24/7 (SLA).                                                                                                                          | Текущая архитектура не обеспечивает этого (один ЦОД). Требуется отказоустойчивая инфраструктура.                         |
| R2  | Система должна автоматически переключаться на резервный ЦОД при сбое основного без потери данных (RPO=0, RTO минимальное).                                                                                           | Сейчас переключение ручное. Необходимо реализовать автоматическое обнаружение сбоев и репликацию данных.                 |
| R3  | Нагрузка на АБС не должна превышать критический уровень; следует исключить синхронные вызовы к АБС из интернет-банка и сайта в новом процессе.                                                                       | Ключевое архитектурное ограничение из-за перегруженности АБС и её вертикального масштабирования.                         |
| R4  | Обработка заявок должна быть надёжной: при сбоях не должно происходить потери данных (использование очередей с подтверждением, транзакций).                                                                          | Обеспечение целостности бизнес-процессов.                                                                                |
| R5  | Кредитный конвейер и система скоринга должны сохранять работоспособность при пиковых нагрузках, используя горизонтальное масштабирование.                                                                            | Эти системы уже поддерживают масштабирование, требуется правильно распределить нагрузку.                                 |
| P   | Производительность (Performance)                                                                                                                                                                                     |                                                                                                                          |
| P1  | Время обработки запроса на подачу заявки в ИБ (включая подтверждение СМС) не должно превышать 3 секунд.                                                                                                              | Обеспечение приемлемого пользовательского опыта.                                                                         |
| P2  | Система должна поддерживать горизонтальное масштабирование компонентов (кроме АБС) для обработки растущего числа клиентов.                                                                                           | Требование к архитектуре новых сервисов (микросервисы, балансировка).                                                    |
| P3  | Обмен данными между новыми каналами и АБС должен быть асинхронным, с использованием очередей сообщений или пакетной обработки.                                                                                       | Снижение нагрузки на АБС и обеспечение отказоустойчивости.                                                               |
| P4  | Время выполнения скоринга для нового клиента на сайте (с паспортными данными) не должно превышать 5 секунд.                                                                                                          | Учитывая внешний вызов БКИ и расчёт модели.                                                                              |
| S   | Поддерживаемость (Supportability)                                                                                                                                                                                    |                                                                                                                          |
| S1  | Код новых компонентов должен быть документирован для дальнейшего расширения (включая архитектурные диаграммы, описание API).                                                                                         | Обеспечение возможности развития силами команды банка.                                                                   |
| S2  | Предпочтительно использовать технологии, уже применяемые в банке (MS SQL, Oracle, Java, Python, .NET). При введении новых (например, Kafka) необходимо наличие внутренней экспертизы.                                | Снижение рисков и затрат на поддержку.                                                                                   |
| S3  | Новый функционал в интернет-банке следует реализовывать в виде отдельного микросервиса (или набора микросервисов) для независимости от монолитного ядра и упрощения доработок.                                       | Позволит избежать зависимости от подрядчика и обеспечит гибкость.                                                        |
| S4  | Должны быть предусмотрены средства мониторинга и логирования для новых сервисов (сбор метрик, алертинг).                                                                                                             | Важно для обеспечения надёжности и быстрого обнаружения проблем.                                                         |
| S5  | Должна быть обеспечена возможность независимого развёртывания новых компонентов (CI/CD).                                                                                                                             | Ускорит вывод изменений.                                                                                                 |
| +R  | + Ограничения (Restrictions)                                                                                                                                                                                         |                                                                                                                          |

| +R2 | Функционал отправки СМС необходимо реализовать силами команды банка, избегая доработок подрядчика ядра ИБ.                                                                                                           | Снижение зависимости и затрат.                                                                                           |
| +R3 | Текущая платформа интернет-банка (.NET Framework 4.5) несовместима с Kafka; при необходимости использования очередей нужно либо выносить новый функционал в отдельные сервисы, либо обновлять платформу.             | Техническое ограничение, влияющее на выбор стека.                                                                        |
| +R4 | База данных АБС (Oracle) масштабируется только вертикально, поэтому нельзя увеличивать количество онлайн-запросов к ней.                                                                                             | Подтверждает необходимость асинхронной интеграции.                                                                       |
| +R5 | Кредитный конвейер и система скоринга поддерживают горизонтальное масштабирование – это должно быть использовано для обработки дополнительного потока заявок.                                                        | Ограничение-возможность, а не препятствие.                                                                               |
| +R6 | Идентификация новых клиентов требует личной явки в отделение согласно законодательству.                                                                                                                              | Юридическое ограничение, влияющее на процесс (клиент должен прийти).                                                     |
| +R7 | Передача и хранение персональных данных должны соответствовать ФЗ-152 и другим нормативным требованиям.                                                                                                              | Обеспечение безопасности и compliance.                                                                                   |
| +R8 | При разработке необходимо учитывать возможность будущего расширения (полная автоматизация открытия депозитов без участия бэк-офиса).                                                                                 | Требование к гибкости архитектуры.                                                                                       |
