### <a name="_qmphm5d6rvi3"></a>**Решение**
1 Выделение отдельного микросервиса Loan Service – это позволяет независимо масштабировать и развивать функционал.

2 Прямая интеграция с Кредитным конвейером через REST API – Конвейер уже имеет API, что позволяет передавать заявки онлайн, минуя ночные пакеты из АБС. Для предодобренных предложений Loan Service может периодически запрашивать у конвейера список предодобренных для клиентов или получать события об обновлении.

3 Интеграция со скорингом – Loan Service вызывает систему скоринга синхронно для новых заявок с паспортными данными, чтобы мгновенно выдать решение. Для предрасчетов предодобренных предложений можно использовать фоновый процесс, который запрашивает скоринг в непиковое время.

4 Асинхронность и очереди – для отправки СМС, обновления статусов в АБС и других фоновых задач используется Kafka. LoanService публикует события (новая заявка, изменение статуса), которые потребляют соответствующие адаптеры. Адаптер АБС, аналогично депозитному решению, пишет заявки в АБС пакетно или по триггеру, не нагружая её синхронно.

5 Единая заявка – LoanService генерирует уникальный ID заявки и передаёт его в Конвейер. При обращении в отделение сотрудник АБС (через доработанный интерфейс) может найти заявку по этому ID или по данным клиента. Для этого АБС должна получить данные заявки через адаптер.

6 Предодобренные предложения – хранятся у Конвейера, как часть данных клиента. LoanService периодически запрашивает их (например, раз в сутки) или получает через Kafka при изменении.

7 Технологический стек – Java Spring Boot (как в кол-центре, есть экспертиза), PostgreSQL, Kafka. Взаимодействие с Конвейером и скорингом через REST.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
1 Расширение Deposit Service для кредитов – экономия на создании нового сервиса, но смешение разной логики и разных бэкенд-систем приведёт к сложности поддержки. Отвергнуто

2 Прямое обращение интернет-банка и сайта к Кредитному конвейеру – конвейер не предназначен для публичных API, может не справиться с нагрузкой и сложно обеспечить безопасность. Отвергнуто

3 Хранение заявок только в Конвейере – тогда при недоступности Конвейера заявки будут теряться. Loan Service с собственной БД обеспечивает надёжность. Отвергнуто

4 Использование синхронной записи в АБС – противоречит требованию не нагружать АБС. Отвергнуто

### <a name="_bjrr7veeh80c"></a>**Недостатки, ограничения, риски**
1 Зависимость от API Конвейера и скоринга – эти системы могут изменяться, потребуется версионирование.

2 Задержки при синхронном скоринге – вызов БКИ может занимать несколько секунд, что может ухудшить пользовательский опыт. Требуется оптимизация и таймауты.

3 Согласованность данных при сбоях – возможна ситуация, когда заявка сохранена в Loan Service, но не доставлена в Конвейер. Необходимы механизмы повторных попыток и компенсации (Saga, Retry).

4 Нагрузка на скоринг при предрасчетах – если запускать предрасчет для всех клиентов каждую ночь, это может создать пик. Нужно распределять нагрузку (например, рассчитывать только активных клиентов, использовать ограничение скорости).

5 Безопасность – Loan Service становится критическим звеном, требуется тщательная защита API (аутентификация, rate limiting).

6 Мониторинг и алертинг – необходимо обеспечить полную наблюдаемость нового сервиса.

7 Интеграция с АБС через адаптер – адаптер должен гарантировать доставку и не терять заявки; требуется тестирование на отказоустойчивость.
